01 / METHOD OVERVIEW

为什么这些方法会针对水下环境？

两条不同路线：从真实水下视频学习域适应，或把水体条件显式注入几何推理。

Wat3R

从真实无标注水下视频中学会适应水下

Wat3R 从通用 feed-forward 3D reconstruction 出发，用 teacher–student 跨域半监督学习吸收大量没有 3D 标注的真实水下视频，并通过 cross-view consistency 利用其他视角的几何信息，缓解衰减、散射和低纹理造成的单视角信息损失。

一句话：不依赖昂贵的真实水下 3D GT，而是靠真实水下视频 + 跨视角几何一致性完成域迁移。

Wat3R project ↗
Water-VGGT

把“现在是什么水况”显式告诉模型

Water-VGGT 面向空气域到水下域的 domain shift，把与折射、可见度下降、散射强度、光谱/波长衰减相关的水体条件表示注入 Transformer，使特征交互和几何推理能够随当前水况变化。

WCV = Water Condition Vector：它是水体条件向量，而不是简单的图像增强参数；论文方法通过条件 embedding、FiLM / conditional attention 等机制参与网络内部推理。

Water-VGGT paper ↗
实现边界：本站的 Water-VGGT+WCV 是本地实验分支——“先做 WCV 条件增强，再送入 VGGT”。它不是论文中把 WCV condition embedding 注入 Transformer 的完整 Water-VGGT 实现，定量结果不能与论文完整方法混为一谈。

06 / DISCUSSION
Q1 · BENCHMARK

GT coverage / filtering 会不会影响 quantitative evaluation？

尤其当动态目标在 RGB 中存在、GT 中缺失，而预测仍重建出该目标时，需要区分“真实预测误差”和“参考覆盖不完整”。

Q2 · MODEL FAILURE

失败发生在 Depth，还是 Point Cloud reconstruction？

用同帧 RGB → Depth → Point Cloud 证据链检查细杆、鱼群、低纹理、浑浊等情况，定位误差开始出现的位置。

Q3 · ROOT CAUSE

瓶颈来自数据，还是 underwater-specific physics？

比较真实水下训练数据的规模/多样性与折射、散射、衰减等物理因素的建模不足，寻找下一步实验方向。

WaterView · local Water3D protocol · Wat3R / DA3 / Water-VGGT / Water-VGGT+WCV
